# Round 3 设计方案

本文件是 Round 3 的实施蓝图。写在 Round 2 真实数据回来之前——决策上下文还在，但动手的人可能是别人。决策依据见 [ADR-0018](adr/0018-round3-is-a-single-composite-confirmation-round.md)，本文件只讲"做什么、怎么做、怎么算通过"。

**一句话定位**：Round 3 是**一次性的复合确认轮**，32 瓶里同时做确认和探索，极可能是最后一轮。不是"换个中心点再跑一个 Round 2"。

## 前置条件

Round 3 的设计生成有三个前提，缺一个就不要开始：

1. **Round 2 的 32 个条件已执行、产量和 OD600 已回填**，且「③ 响应面结果」子页能正常出结论（R²、失拟检验、最优点、置信区间都有值）。
2. **看过「④ 合并数据贝叶斯优化」的 Q²**。Q² 很低（<0）时下面 BO 候选那 8 瓶的价值要重新评估——见「预算分配」的注释。
3. **⚠️ 人工决策门：看 Round 2 那 2 个 36h 交互点的结果。** 这一步不能自动化，需要研发组看着数据判断。它决定预留的 6 瓶怎么花，见下。

## 预算分配：32 瓶

| block | 建议 run_type | 点数 | 作用 |
|---|---|---|---|
| 确认-预测最优点 | `confirmation` | 4 重复 | **主交付判据**：实测 vs 预测。4 个重复才够给出一个像样的均值和本点噪声 |
| 确认-满意度折中点 | `confirmation` | 3 重复 | OD600 若是真约束，这才是能落地的点；和上一行是两个不同的候选工艺 |
| 基线对照 | `baseline` | 3 重复 | 直接给出"相比现状提升多少"，同时提供**本轮独立的噪声估计** |
| 岭线 / 最优点邻域扫描 | `ridge_scan` | 8 | 这个最优点稳不稳、能不能挪到更省成本的位置 |
| BO 候选 | `bo_candidate` | 8 | 确认失败时唯一的备选来源；同时继续喂 GP |
| 预留（按诊断花） | 视情况 | 6 | 见下 |

合计 32。

### 三个 block 的细节

**确认点怎么取。** 最优点来自 Round 2 的 `fit.optimum`；满意度折中点来自 `optimize_joint_desirability` 的 `point`。如果这两个点几乎重合（OD600 约束没有真正起作用），把折中点那 3 瓶合并进最优点，做 7 个重复——重复数越高，确认结论越硬。

**基线对照为什么必须有。** 两个作用，都不能省：一是"提升多少"这个问题只能靠同批次的基线回答，跨轮比较会混进批次效应；二是本轮自己的噪声估计——有了它才能**用数据判断**轮间是否存在批次效应（把本轮基线噪声和 Round 1 的对比），而不是先拍一个"能不能池化"的假设。

**岭线扫描的方向怎么定。** 需要先给 `CanonicalAnalysis` 加 `eigenvectors` 字段（`np.linalg.eigh` 本来就同时返回，现在丢掉了）。分两种情况：

- Round 2 判为 `ridge`（有近零特征值）→ 沿该特征向量方向，在已测范围内均匀取 8 点（含最优点两侧）
- Round 2 判为 `maximum`（真峰）→ 没有岭线方向可扫，改为最优点邻域：沿 3 个变量各取 ±1 个小步长（6 点）+ 2 个对角点，回答"偏离最优点多少产量才明显掉下去"（这是 `sensitivity_analysis` 给的 plateau 宽度的实测验证）

### 预留 6 瓶怎么花

**按 Round 2 的诊断决定，优先级从上到下：**

1. **36h 看起来更好**（最可能用到的情况）→ 全部 6 瓶给 36h：在 24h 最优点的相同变量组合上做 36h × 3 重复，加 36h 下的 1-2 个邻域点。目的是让 ADR-0018 决策 5 那条警告有数据支撑，而不是只凭 Round 2 的 2 个点。**注意这 6 瓶不是为了在 36h 重建响应面**（那要另一个 CCD，18 点起），只是为了把"36h 值得单独再走一轮"这个结论说实。
2. **失拟显著** → 6 瓶补 CCD 中心点和轴向点，提高对高阶项的分辨力
3. **Q² < 0（GP 完全不可信）** → 6 瓶改成纯 LHS 空间填充点，同时考虑把 BO 候选那 8 瓶也部分改成 LHS——BO 建议的可信度直接取决于 Q²
4. **以上都不成立** → 加到确认点的重复数上（最优点 4→7 重复），把确认结论做得更硬

## 验收：两个判据，都报，不合并

按 ADR-0018 决策 4，软件同时给出两个判据的数据和口径，**不给单一的通过/不通过**，决策由研发人员做。

### 判据 A：统计一致性 —— 响应面模型对不对

比较确认点的实测均值和模型预测。

**⚠️ 实现要点：不能直接拿实测均值去比现有的 `predict_with_confidence_interval`。** 那个函数给的是"平均响应"的置信区间（Var = mse·x₀ᵀ(XᵀX)⁻¹x₀），没有包含新观测自身的抽样误差。正确的比较对象是 **n 个新观测均值的预测区间**：

```
半宽 = t(1-α/2, df_residual) × √( mse·x₀ᵀ(XᵀX)⁻¹x₀ + mse/n )
```

多出来的 `mse/n` 就是 n 个重复自身的抽样误差。直接用现有 CI 会**偏严**——把观测自己的波动算成了模型的错，好模型也会被判不一致。`ResponseSurfaceFit` 已经带了 `mse`/`xtx_inv`/`df_residual` 三个字段，够算，不需要改拟合。

结论口径：
- 实测均值落在预测区间内 → 响应面在最优点附近可信
- 落在区间外 → 模型在最优点附近不可靠。要在界面上说清是**高于**还是**低于**预测：低于预测说明模型高估了最优点（更常见，也更该警惕）；高于预测说明还有没探到的上升方向

### 判据 B：工艺改动门槛 —— 值不值得改

比较确认点实测均值和**同批次基线**实测均值：

```
提升 = 确认点均值 − 基线均值
门槛 = 2 × 本轮噪声SD（由 3 个基线重复估计）
```

结论口径：
- 提升 > 门槛 → 有统计上站得住的提升，值得提交工艺团队评估
- 提升 ≤ 门槛 → **"现有工艺已接近最优，不建议改"**。这同样是一个有价值的交付结论，不是失败——它把"要不要动工艺"这个问题关掉了

### 两个判据的四种组合

这是研发人员真正要看的表，界面上应该直接给出落在哪一格：

| | 提升 > 门槛 | 提升 ≤ 门槛 |
|---|---|---|
| **实测在预测区间内** | 模型对、提升够 → **收工交付**，附 plateau 宽度作为操作窗口 | 模型对，但最优点其实没比基线好多少 → **收工，结论是不建议改工艺** |
| **实测在区间外** | 提升是真的，但模型没预测准 → 可以交付这个实测点，但**不要**再用这个响应面外推别的点 | 模型不对、也没提升 → 手上的 8 个 BO 候选实测点是 Round 4 的起点（若还有探索价值） |

## 能原样复用的（不要重写）

- **Excel 导出 / 上传回填 / 逐格回填 / 存盘**：`App/pichia_results_io.py` 的 `_pichia_round2_workbook_bytes` 和 `_pichia_remap_uploaded_columns` 对"设计表"是通用的，只要新 run_type 有标签和配色就能用
- **所有分析函数**：响应面拟合、置信区间、灵敏度、canonical、满意度、BO、留一法交叉验证——它们吃的是"变量列 + 结果列"的表，不关心是第几轮
- **BO 的叙述解读和交叉验证界面**：`_pichia_render_bo_recommendation_section` 的 `train_df`/`cv_session_key` 是参数而不是硬编码，正是为了这种复用（见 ADR-0016/0017）

## 明确不做

- **不做通用的多轮循环框架**（ADR-0018 决策 2、3）。总共 2-3 轮，为想象中的第 4 轮做抽象是纯浪费
- **不让 `interval_h` 进入响应面**（ADR-0018 决策 1）。K 永久为 3
- **不为"36h 更好"改分 Round 3 预算**（ADR-0018 决策 5）。交付 24h 方案 + 警告，预留 6 瓶只用于让警告有据可查
- **不把两个验收判据合并成单一结论**（ADR-0018 决策 4）。软件不自动授权工艺变更

## 验收（落地时怎么验证）

1. `assemble_round3_design` 的单元测试：6 个 block 的点数和 run_type 正确、总数 32、同种子两次调用完全一致、确认点坐标等于传入的 `fit.optimum`
2. 预测区间的单元测试：`n_observations` 越大区间越窄、n→∞ 时收敛到现有 `predict_with_confidence_interval` 的结果、noiseless 拟合下区间宽度为 0
3. 确认判据的单元测试：四种组合各构造一组数据，断言落在正确的格子里；特别测"实测均值刚好在旧 CI 外但在新预测区间内"这种情况，防止有人把预测区间换回置信区间
4. AppTest 端到端：用 Round 2 的合成数据链条继续往下走，生成 Round 3 设计 → 下载 → 模拟回填 → 出两个判据和四格定位，全程无异常
5. 真实数据回填后，**四格定位落在哪一格要由研发人员核对是否符合直觉**——软件只保证算得对，不保证结论合理
