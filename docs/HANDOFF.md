## 下一步

Round 2 页签内部分成四个子页：**① 显著性分析 / ② 设计生成与回填 / ③ 响应面结果 / ④ 合并数据贝叶斯优化**。走法是先在②生成设计表、把实测结果填回去，③④才有内容（没数据时它们会提示指回②，不是空白页）。注意 `st.tabs` 不做懒加载——停在①时③的拟合照样在跑，分页解决的是导航，不是速度（见 `docs/adr/0017`）。

1. 在 Round 2 → **②设计生成与回填** 子页，用"生成完整 Round 2 设计"拿到 32 个条件的设计表（Excel 下载），确认已经排期/执行的批次和这份设计一致。
2. 摇瓶实验执行后，记录每个条件的产量与 OD600，通过同一子页的"上传已回填结果"传回（也可以直接在下面的表格里逐格填）。
3. 检查 **③响应面结果** 子页：CCD 响应面的 R²/失拟检验是否合理、补料间隔交互检验的结论；再看 **④合并数据贝叶斯优化** 子页要不要用来生成 Round 3 候选——这几块逻辑见 `docs/adr/0009` 到 `0013`。
4. 响应面的可视化（等高线图、系数表、残差图）、以及点估计之外的四项深入分析（置信区间、灵敏度、鞍点/岭线判别、产量+OD600联合满意度，其中灵敏度/鞍点/联合满意度三项现在也各配了一张图，见 `docs/adr/0014`）都已经接到界面上并通过合成数据验证；真实数据回填后重点核对这四项深入分析在四种边界情况（失拟显著/最优点卡边界/OD600不可行/一切正常）下给出的文案和真实数据是否对得上。
5. 贝叶斯优化只剩一个入口——**④合并数据贝叶斯优化** 子页（Round1+Round2 合并数据训练，见 `docs/adr/0009`）；原来还有一个"仅用 Round1 数据"的预览入口和依赖它的"历史记录"页签，2026-08-12 已确认删除（见 `docs/adr/0016`，因为 Round 2 的实际设计早就照 CCD 方法论定下来了，那个预览入口的建议从没被采纳过）。它的"模型校验（留一法交叉验证）"折叠框需要手动点按钮才会跑（几秒到几十秒），见 `docs/adr/0015`；仅用 Round 1 真实数据跑出来的产量模型 Q²≈0.13，明显偏弱——数据量增加后应该重新点一次这个按钮，确认 Q² 有没有随数据变多而改善，再决定贝叶斯优化推荐能不能直接采用。

## 改代码前先看这张表

Pichia 页面在 `App/` 下分成这几个文件（见 `docs/adr/0017`，那里也写了新函数该往哪儿放）：

| 文件 | 装什么 |
|---|---|
| `pages_pichia.py` | 只有顶层 Round 1 / Round 2 页签路由（33 行） |
| `pichia_common.py` | 路径常量、中文标签、配色、两轮共用的行级展示辅助；**不 import 任何其他 pichia 模块** |
| `pichia_results_io.py` | 设计表导出 Excel、回传结果解析（单位标注/未检测到/技术重复取均值都在这儿），纯函数 |
| `pichia_round1.py` | Round 1 构建器、两张结果图、页签 |
| `pichia_round2_surface_views.py` | 响应面的表格/图表/叙述解读；**纯视图层，不碰 session_state、不拥有 widget key** |
| `pichia_round2_bo_views.py` | BO 推荐表、GP 偏依赖图、留一法交叉验证、BO 解读 |
| `pichia_round2_sections.py` | Round 2 四个子页的小节 + 页签本体；**页面状态只在这个文件里** |
