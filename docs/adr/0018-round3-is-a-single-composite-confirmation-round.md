# ADR-0018：Round 3 是一次性复合确认轮，不是循环的一次迭代

## 元数据

- 决策发生时间：2026-08-12（本次会话）
- 本记录补记时间：2026-08-12

## 背景

Round 2 的 32 个条件已生成、等待执行。在讨论"Round 3 该怎么设计、能不能直接复用 Round 2 的流程做成循环"时，先确认了两个此前没写下来的项目约束：

1. **总共 2-3 轮收工**，除非 Round 2 暴露出还有探索价值。也就是说 Round 3 极可能是最后一轮。
2. **每轮预算 32 瓶**（物理上限 40）。

再加上对补料间隔的工艺澄清（下面决策 1），这两条把"Round 3 是什么"这个问题的答案锁死了，值得记下来——否则接手的人看到 Round 1 → Round 2 的递进，很自然会以为 Round 3 就是"再跑一遍 Round 2"。

## 决策

### 1. K 永久等于 3；`interval_h` 永不成为设计变量

补料间隔在这条工艺里**只会取一个固定值**（设备与排期约束，不是数据问题）。因此活跃变量永久是 `glucose_pct`/`ph`/`volume_ml` 三个，响应面永远是 3 维。

这关闭了 ADR-0012 留下的开放项（"等 36h 真实数据回填后，`FIXED_LEVELS` 要不要正式扩展，需要另外评估"）：**不扩展**，而且结论方向和 ADR-0012 一致，只是理由更强——从"数据还不足以支撑外推"升级为"它根本不是一个可探索的维度"。`tests/test_round2_design.py::test_interval_h_fixed_levels_excludes_untested_36h` 那条断言因此从"临时保护"变成"永久约束"。

Round 2 的 36h 交互子设计仍然有意义，但它回答的问题变了：不是"要不要加一维"，而是**"该把这个固定值定在哪一档"**——一次性的离散选择。

### 2. Round 3 是单次复合设计，不是循环的一次迭代

Round 3 用一份 32 瓶的复合设计，同时做确认和探索（具体分配见 `docs/ROUND3_PLAN.md`），不是"换个中心点再跑一个 Round 2"。

理由：Round 3 极可能是最后一轮，**它必须自给自足**。既要拿出能交付给工艺团队的确认结论，又要在确认失败时手里已经有能解释原因、能给备选的数据——没有"下一轮再补"这个退路。把 32 瓶全押在确认上（确认失败就一无所有），或者全押在探索上（拿不出可交付结论），两种都是错的。

顺带否掉了一个曾经考虑过的方案："把响应面流程做成循环，每轮诊断后自动生成下一轮 CCD"。Round 2 的诊断有五种走向（正常-真峰 / 正常-岭线 / 卡边界 / 失拟 / OD600 不可行），需要五种**结构不同**的后续设计。做成"再来一个 CCD"会在真峰（该收工确认，却又烧 32 瓶探索）和岭线（该沿方向扫描，却又铺方形网格）两种情况下给出**错误的**设计。响应面是每几轮做一次的诊断工具，不是循环的一环；真正天然可循环的只有贝叶斯优化那条线（ADR-0009），而 2-3 轮的总量下它也只会再跑一次。

### 3. 不做通用的 round-indexed 数据存储

现在是 `round1_results_df`/`round2_full_design_df` 两个硬编码 session key + 两个 CSV 路径，`combined_df` 从两个槽硬拼。Round 3 **直接加第三个具体的槽**，不改成 round-indexed 长表或通用的多轮存储。

理由：总共 3 轮，通用化和加一个具体槽的工作量差不多，而通用化在第 3 轮之后没有任何回报。这是一次明确的"不为想象中的第 4 轮做抽象"。

### 4. 确认判据同时报两个，软件不合并成一个结论

- **统计一致性**：实测均值落不落在模型的预测区间内 → 回答"响应面模型对不对"
- **工艺改动门槛**：相对基线的提升是否超过 基线 + 2×噪声 → 回答"值不值得改工艺"

两个都报，**不合并、不加权、不给单一"通过/不通过"**。理由：这两件事经常不一致（模型很准但提升不值得改；或提升很大但模型没预测准），而工艺团队真正要的是第二个。软件的职责是把两个判据的数据和口径讲清楚，决策由研发人员做——延续"软件不自动授权实验"这条硬约束。

### 5. 36h 若优于 24h：交付 24h 方案 + 明确警告，不改分预算

Round 2 的 CCD 18 点是在 round 1 定下来的那一档（数据里基线是 24h）上做的，36h 只有 2 个交互点 + 2 个噪声参考点。所以"36h 更好"这个结果有个尴尬后果：**手上的响应面描述的是 24h 的工艺，而更优的操作点在 36h**，严格来说需要在 36h 重建整个响应面。

**决策：不为此改分 Round 3 的预算。** 仍然按计划交付 24h 的确认结论，同时在界面和交付物上明确警告"36h 观察到更高产量，但当前响应面（含最优点、置信区间、灵敏度、满意度）全部基于 24h 数据；要把 36h 作为工艺条件，需要在 36h 重建响应面，那是另一轮的工作量"。预留的 6 瓶用来加强 36h 的证据（见 `docs/ROUND3_PLAN.md`），让这条警告有数据支撑，而不是只凭 2 个点。

理由：24h 有 18 点响应面支撑，36h 只有 2 点。用一个证据充分的档位收工、并把 36h 作为**有据可查的遗留线索**交出去，比用 2 点证据推翻 18 点、重开一轮更划算——尤其是在 2-3 轮收工的预算下，重建响应面等于直接放弃"3 轮收工"。

### 6. 岭线情况现在就支持，但必须能解释失败

给 `CanonicalAnalysis` 增加 `eigenvectors` 字段（`np.linalg.eigh` 本来就同时返回，现在丢掉了），沿近零特征值对应的方向布点扫描。

允许这个分析给不出漂亮结论，但**不允许它默默给出一个不可信的方向**。失败时必须用三个已有的量说清是哪一种失败：特征值的相对大小与判定用的 `ridge_tolerance`（"近零"近到什么程度）、`stationary_point_reliable`（区分"真的平"和"矩阵接近奇异、方向本身不可信"）、以及扫描后实测沿线的波动 vs 本轮噪声（波动小于噪声=真平，结论成立；大于噪声=岭线判定错了）。

## 后果

- Round 3 要新写的只有两块：**设计生成**（`assemble_round2_design` 的 4 个 block 和 Round 3 需要的 6 个完全不同）和**验收判据**（Round 2 里没有这个概念）。Excel 导出/上传回填/存盘那一整套，以及响应面拟合、置信区间、灵敏度、满意度、BO、交叉验证全部原样复用——它们吃的是"变量列 + 结果列"，不关心第几轮。
- 需要新增 run_type：确认点、基线对照、岭线/邻域扫描、BO 候选。现有 7 个 run_type（baseline/ofat/combo/ccd/interval_interaction/noise_reference/lhs）不够。
- **Round 3 的设计生成有一个前置决策门**：必须先看 Round 2 那 2 个 36h 点的结果，才能确定预留的 6 瓶怎么花。这个门不能自动化——它需要研发组看着数据做判断。
- 确认判据要比较的是 n 个重复的实测均值，正确的比较对象是**预测区间**（半宽 = t × √(mse·x₀ᵀ(XᵀX)⁻¹x₀ + mse/n)），比"平均响应的置信区间"宽；直接用后者会偏严，把观测自身的抽样误差算成了模型的错。**这一项和 `CanonicalAnalysis.eigenvectors` 已于本次会话提前实现**（两者都无条件需要、都是纯函数、都能用合成数据充分验证，且都独立于 Round 3 有价值——eigenvectors 顺带让 Round 2 的特征值图从"曲率方向 1/2/3"变成按因素命名）。Round 3 其余部分仍未动，见 `docs/ROUND3_PLAN.md` 的「待做」。
- 项目可能在 Round 3 就收工，也可能得出"现有工艺已接近最优、不建议改"——后者同样是一个有价值的交付结论，不是失败。
