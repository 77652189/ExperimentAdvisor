# ADR-0020：回填结果在读取阶段规范化，「未检测到」按 0 而非缺失值

## 元数据

- 决策发生时间：2026-08-11（回填第一批真实 Round 1 数据时）
- 本记录补记时间：2026-08-13（`canon` 会话挖掘发现该决策未入 ADR）

## 背景

Round 1 的实测结果由实验人员填在 Excel 里再上传，表格内容不是干净的数值：

- **表头带单位标注**，例如产量列写成 `产量 (mg/L)`，而仓库内部统一用 `yield_g_per_l`
- **单元格里有文本结果**，例如低于检出限时填「未检测到」
- **同一 `run_id` 出现多行**（技术重复）

这三件事必须在某处被规范化。当时定了在哪一层做，以及「未检测到」到底算什么。

## 决策

### 1. 规范化在读取阶段完成，不在分析阶段

`_pichia_remap_uploaded_columns`（`App/pichia_results_io.py`）在上传回填时一次性完成：识别单位标注并换算、把文本结果转成数值、把同 `run_id` 的技术重复取均值。落盘的 run-level 数据集因此是**唯一口径**，下游所有分析拿到的都是同一份规范化结果。

**否掉的方案：在分析阶段各自换算。** 效应筛选、响应面拟合、BO、可视化都要读产量列，每处重复一遍换算逻辑，漏一处就是静默的量级错误——而 mg/L 与 g/L 差 1000 倍，错了不会报错，只会让结论悄悄不成立。

技术重复取均值时**原始值不丢弃**：`<col>_n`（重复数）、`<col>_spread`（极差）、`<col>_reps`（原始值，`|` 连接）随均值一起存。这是 ADR-0011 能把技术噪声当独立诊断的前提。

### 2. 「未检测到」按 0 处理，不按缺失值

**否掉的方案：按 `NaN` / 缺失值处理。** 缺失值会在任何 `dropna` 或聚合里被静默剔除，而「低于检出限」恰恰是 Round 1 最重要的信号——本轮的交付是「哪些方向会塌」，塌到检出限的那些点如果从数据里消失，整轮结论就没了。按 0 保留，它们才能进效应量计算并把方向标出来。

## 后果

- **按 0 会低估真值，这是已知代价。** 检出限以下不等于 0，只是「小于某个值」。当某个条件的产量落在检出限附近，均值会被拉向 0。
- 这不是理论顾虑：真实 Round 1 里**有一个条件的两个技术重复是（一个极小值，0）**，正好落在这个情形上。它的效应量因此偏大——但方向（该条件产量塌了）不受影响，而本轮只用方向。
- **进入响应面阶段后这条要重新审。** 二次模型对「一侧塌到底」的强非线性拟合能力有限，而按 0 处理会加剧这种形状。真实 Round 2 数据回来后如果失拟检验显著，**先怀疑数据形态和这条约定，再怀疑模型**。
- 若将来需要更严谨的处理，标准做法是删失数据（censored regression）或代入 LOD/2，两者都需要知道检出限的具体值——目前没有记录。**要走这条路得先向研发组问到 LOD。**
