# ADR-0014：响应面深入分析四件套——置信区间、灵敏度、鞍点/岭线判别、联合满意度

## 元数据

- 决策发生时间：2026-08-12（本次会话）
- 本记录补记时间：2026-08-12

## 背景

ADR-0013 落地后，`fit_ccd_response_surface` 已经能给出一个点估计的"最优点"，`summarize_response_surface` 也能给出一句话结论（失拟/卡边界/OD600不可行/一切正常）。但点估计本身留了几个没回答的问题：

1. 这个"最优点"的产量预测值有多可信？—— 只有一个数字，没有不确定度。
2. 最优点附近这几个变量能不能有点浮动？—— 网格搜索只回答"哪里最高"，不回答"周围多宽的范围也差不多高"。
3. 网格搜索给出的点，是不是真的是一个"峰"？—— 网格搜索在有界区域内永远能返回某个点，哪怕拟合出来的曲面其实是鞍点或者一条岭线（某个方向根本没有曲率），网格搜索也照样"找到"一个点，看不出这个点和真正的峰有本质区别。
4. 产量最优点在 OD600 上不可行时，除了"别用这个点"，有没有更具体的备选？—— `recommend_round2_bo_batch` 的做法是硬过滤（不可行的候选直接扔掉），但这是在做候选推荐，不是在解释"这批 CCD 数据本身在说什么"。

同时用户提出：四个新分析要按失拟/卡边界/OD600不可行/一切正常四种情况给出有区分度的内容，而不是四种情况下展示同一套东西；并且要在表头等位置加悬浮提示解释术语。

## 决策

1. **置信区间只对"拟合曲面的均值"，不对"单次新测量"**：`predict_with_confidence_interval` 用标准 OLS 公式 `Var(ŷ(x0)) = MSE·x0'(X'X)⁻¹x0`，复用 `fit_ccd_response_surface` 已经算出的 `mse`/`xtx_inv`（为此给 `ResponseSurfaceFit` 新增这两个字段+`df_residual`，不重新拟合、不用 bootstrap）。这回答的是"这批数据换一批重做，这个点的预测值会不会明显不一样"，不是"下一瓶实际测出来的产量落在什么范围"——两者是不同的问题，后者还要再加一个 `mse` 项，本次不做。
2. **灵敏度分析是"最优点附近的局部读数"，不是"整条曲线的全局形状"**：固定其余活跃变量在联合最优点，单独扫一个变量，找预测值不低于峰值 95% 的连续区间（"容许范围"）。这是局部问题（"这个变量能有多大浮动"），和第 3 点的鞍点/岭线判别（"曲面到底是不是真的有峰"）是两个独立的问题，不能互相替代——一个变量可以有很窄的容许范围，同时曲面整体仍然是个规规矩矩的极大值。
3. **鞍点/岭线判别用经典响应面 canonical analysis（特征值分解），阈值相对于最大特征值，不用精确等于0判断**：把拟合系数还原成二次形的 B 矩阵（对角是二次项系数，非对角是交互项系数的一半），对 B 做特征值分解；`|特征值| < 0.05 × max(|特征值|)` 才算"这个方向没有曲率"——拟合出来的系数几乎不可能精确为 0，卡精确 0 的判断永远不会触发。无约束理论最优点用 `lstsq`（不是 `solve`）求，B 奇异/近奇异时也不会抛异常；同时显式给出 `stationary_point_reliable`（鞍点以外的退化情形——岭线/近似平坦——为 False），避免把一个数学上算出来但没有实际意义的点当成正常结果直接展示。
4. **产量+OD600 用 Derringer-Suich 满意度联合优化，和 `recommend_round2_bo_batch` 的硬过滤是两条并行的路，不是互相替代**：两个响应面各自打 0~1 分（产量用两侧渐变，OD600 用到阈值封顶的单侧渐变），几何平均做联合打分，在和点估计优化相同的"已测范围网格"上找联合最优点。刻意不用硬过滤，因为这里要回答的是"为了让 OD600 达标，产量具体要让多少"，而不是"给一批新候选去试"——两个问题的答案不需要一致，也不需要用同一种方法回答。
5. **四个分析的判据和 `summarize_response_surface` 的结论判据必须是同一份代码**：新增 `classify_response_surface_case`，把"失拟>卡边界>OD600不可行>一切正常"的优先级判断抽成独立函数；`summarize_response_surface` 自己的"下一步建议"和 UI 层四个深入分析的差异化文案都调用这一个函数，不允许各自维护一份条件判断——否则两处的判断迟早会因为改了一处忘了改另一处而不一致。

## 后果

- `ResponseSurfaceFit` 新增 `mse`/`xtx_inv`/`df_residual` 三个字段；由于 `fit_ccd_response_surface` 已经在 `n_points <= n_params` 时提前抛错，`df_residual > 0` 在能构造出 `ResponseSurfaceFit` 的前提下必然成立，不需要额外的"样本不足"分支。
- 四个新分析都是纯函数，只读一个已经拟合好的 `ResponseSurfaceFit` + 对应的数据框，不需要新的拟合、不额外要求数据——`fit_ccd_response_surface` 能跑通，这四个就都能跑。
- UI 层（`_pichia_render_response_surface_deep_dive`）四种情况下都渲染全部表格，从不整体隐藏——即使处于"存在显著失拟"，表格仍然展示，只是前面加一条醒目提示；隐藏数据不如展示数据+说明数据现在不完全可信。四种情况的区分体现在：默认展开哪个折叠框（`boundary`默认展开鞍点判别，`od_infeasible`默认展开联合优化）、以及是否额外出现一条针对该情况的具体结论文案（比如`boundary`时如果鞍点判别显示"岭线"，会直接说明这和"卡边界"是同一件事的两种表现）。
- 表头提示统一放在 `pages_pichia.py` 侧用 `st.column_config.Column(help=...)`，`round2_design.py` 不感知任何中文/UI 概念——延续 ADR-0005/既有 verdict 翻译的分层原则。

## 验证

- `tests/test_round2_design.py` 新增约 15 条测试：`classify_response_surface_case` 复用 `summarize_response_surface` 四个既有分支的原始构造数据做交叉验证；`predict_with_confidence_interval` 用无噪声数据验证零宽区间、用加噪数据验证区间对称且离设计中心越远越宽；`sensitivity_analysis` 用能手算容许范围宽度的二次函数验证（一个严格落在测试范围内部、一个被测试范围卡住两侧）；`canonical_analysis` 分别构造真极大值/真极小值/鞍点/岭线四种精确的特征值符号组合；`optimize_joint_desirability` 用先跑一遍实际输出确认经验行为、再回填断言的方式构造（避免手算联合优化的确切落点，只断言结构性质：产量让步、OD600 达标、composite=√(yield_d×od_d)）。
- `App/pages_pichia.py` 侧通过 AppTest 脚本验证（未写入 `tests/`，一次性验证脚本）：真实 Y103 数据全流程无异常，四个新展开框正确出现；另外单独构造四种边界情况直接调用 `_pichia_render_response_surface_deep_dive`，确认每种情况下警告/提示/成功文案和默认展开状态都符合预期，互相之间确实不同。
