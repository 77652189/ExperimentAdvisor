# ADR-0003：大肠杆菌发酵罐路径保留为历史参考，不作为 hLF 决策依据

## 元数据

- 决策发生时间（推断自会话记录）：2026-05-19（大肠杆菌/HMO 发酵罐架构成形）～2026-05-28（一个"毕赤酵母也走发酵罐、多菌株、单轮最多 4 罐"的过渡方案，后放弃）
- 本记录补记时间：2026-07-31

## 背景

历史大肠杆菌/HMO 发酵数据来自跨越多种菌株、时间跨度很大的发酵罐运行，变量又多又杂（`ingestion/run_level.py` 的 `CONTROL_FEATURES` 至今仍是 15 项发酵罐特有变量：分阶段温度、双路补料时间表、乳糖添加时间等）。这种异质性和变量结构本身就不适合训练任何可靠模型。

围绕这份历史数据搭建的推荐软件（qNEI 标准 GP-BO，见 ADR-0004）本身已经完整开发完成，但一直没有获得开展新发酵实验的授权，实验数据也一直不足——不是软件被验证有问题后主动放弃，而是始终没有机会真正投入使用，被迫闲置。数据质量问题和授权/数据缺口这两个原因加在一起，才是转向从零开始的毕赤酵母摇瓶路线（见 ADR-0001）的完整背景。

2026-05-28 前后还短暂讨论过一个毕赤酵母走发酵罐、多菌株、单轮最多 4 罐（人手不足时 2 罐）的过渡方案，并提到要加菌种选择和实验方法选择模块。这个方案在摇瓶路线定型前就被放弃，对应的菌株选择/借鉴框架代码从未在当前代码库留下痕迹（已核实 `App/` 下搜不到"菌株"相关逻辑）。

## 决策

保留 `experiment_advisor/ingestion/`、`experiment_advisor/optimizer/`、`experiment_advisor/recommendation/service.py` 及 `App/pages_legacy_ecoli.py` 这条完整的大肠杆菌发酵罐路径代码，包括 Streamlit 侧边栏"大肠杆菌 BO（历史，数据已作废）"入口，不做删除。该路径仅供理解历史实现，不得作为当前毕赤酵母 hLF 决策的证据来源。

## 后果

以后如果有人疑惑"为什么代码里还有一整套发酵罐 UI/逻辑却没人用"，答案在这里，不需要猜是不是忘了清理。如果确定不再需要保留，删除该路径需要一条新 ADR 取代本条，而不是直接删代码。

## 取代关系

无（是对 ADR-0001 的具体化，不取代它）。
